# Decisions

Append-only log of judgement calls made while building musicbutler
(docs/PLAN.md §0). One line per call: `<date> | <decision> | <why>`.

2026-09-09 | Pin TypeScript 5.9.3 instead of npm `latest` (7.x) | TS 7 (native port) changes `types` resolution and some flags; the Mantine and CodeMirror ecosystems target 5.9. Revisit after v1.
2026-09-09 | `trustedDependencies` lives in the root package.json, not bunfig.toml | Bun reads that field from package.json only; `bun pm trust --all` writes there too. bunfig.toml documents the fact (§13.15).
2026-09-09 | `Bun.file`/`Bun.write` usage outside `apps/server/src/fs/` is guarded by a unit test, not by Biome | Biome's `noRestrictedImports` covers `node:fs` imports; a global cannot be import-restricted. The test greps the source tree.
2026-09-09 | apps/web tsconfig includes the "bun" types | `import type { AppRouter }` pulls the server source into the web type program; without Bun/node globals the web typecheck fails. Web code must still not use those globals (Biome noRestrictedGlobals would be the guard if it ever becomes a problem).
2026-09-09 | `packages/lrc`: `MetaTag` has no `raw` field | `parse` never populates it and `serialize` writes the canonical `[key:value]`, so a `raw` set during parse could not survive the mandated `parse(serialize(doc))` deep-equal. A dead optional field is worse than none.
2026-09-09 | `packages/lrc`: `parse` keeps `lines` in document order; only `serialize` sorts | §5.6 puts the sort in the canonical output. Keeping source order lets `sourceLine` and the multi-tag expansion stay truthful; the round-trip test normalises (sort, drop `sourceLine`).
2026-09-09 | `packages/lrc`: garbage lines (plain text, `[Chorus]`, `[1:2]`, `[99:99.99]`) are dropped from `LrcDocument.lines` and not reported by `validate` | A `Line` needs a time. Plain lyrics pasted before a sync are the normal input, so an "untimed line" diagnostic on every line would bury the real findings. `validate` reports malformed tags; `stripToPlainLyrics` works on the text, so nothing is lost.
2026-09-09 | `packages/lrc`: text before the first `<mm:ss.xx>` word tag becomes a word timed at the line time | Keeps `Line.text` equal to the joined words and makes the enhanced-LRC round trip lossless without a second "prefix" field.
2026-09-09 | `packages/lrc`: `validate` positions a multi-tag line by its earliest tag and does not compare the tags on one line with each other | `[00:10][00:50]chorus` then `[00:15]verse` is the legitimate repeated-lyric idiom; comparing against the last tag seen would flag it. Equal times are the `info` duplicate only, not also the `warning`.
2026-09-09 | `packages/lrc`: `shiftTimestamps` keeps three fraction digits and the minute width when the source tag had them; otherwise writes `mm:ss.xx` | A 10 ms offset step must not truncate a millisecond-precision file. Minimal edit, per §7.6.
2026-09-09 | `packages/lrc`: `parseTime` tolerates one pair of surrounding `[]`/`<>` | The editor mode and tests hand it whole tags; stripping one bracket pair costs one line and avoids a second helper.
2026-09-09 | `packages/lrc`: `stripToPlainLyrics` removes any tag matching the §7.5 shape, including `[99:99.99]`, and drops any line that is one bracket group | The engine wants words, not tags; a shaped-but-invalid tag is still a tag. `[Chorus]`, `[Verse 1]` and metadata all fall under "one bracket group", so one regex covers §8.2 rule 1.
2026-09-10 | `packages/align`: `MODELS.asr["it-IT"]` stays empty; `it-IT` is reported unavailable | No Transformers.js-loadable ONNX export of an Italian wav2vec2 CTC model exists on Hugging Face (checked onnx-community, Xenova, `wav2vec2 italian` search; `FinDIT-Studio/wav2vec2-large-xlsr-53-italian-onnx` has a root-level 1.26 GB fp32 `model.onnx` + `tokenizer.json` but no `config.json`, `preprocessor_config.json` or `onnx/` folder). Exporting with optimum-cli is out of scope for this repository. README lists the checks and the enable path via `MUSICBUTLER_ASR_IT`.
2026-09-10 | `packages/align`: the normalizer follows the vocabulary's case (upper when it holds "A", lower when it holds "a") | The engine doc says "upper case", which holds for `Xenova/wav2vec2-base-960h`; every Italian CTC candidate (jonatasgrosman, dbdmg, facebook xlsr-53-italian) is lower case. A hard-coded upper-case rule would make every Italian word unalignable.
2026-09-10 | `packages/align`: `make-fixture.ts` renders with `--data-format=BEF32@44100`, not `LEF32` | AIFF is big-endian; `say` rejects LEF32 for an `.aiff` output ("Opening output file failed: fmt?"). Same float32 44.1 kHz content.
2026-09-10 | `packages/align`: `SyncResult` carries `lines`; `SyncOptions` adds `returnVocals`, `threads`, `demucsModelPath`, `asrModelId`, `signal`; per-call `{ signal, onProgress, outName }` | The server needs the line array to rebuild the LRC through `packages/lrc` with `leadInMs`, an abort per job, and the CLI needs the vocals for `--verbose` without writing them. All additive to §5.11.
2026-09-10 | `packages/align`: `OverlapAdd` skips the fade-in at sample 0 and the fade-out at `total` | The accumulated weight is then exactly 1 everywhere (the M3 "weights >= 1" check holds at the edges too); the normalised output equals the infer.py result, only the conditioning differs.
2026-09-10 | `packages/align`: the trellis unit tests give the blank a secondary share inside a token run | With one loud class per frame every frame of a run costs the same, so the alignment inside the run is a float-rounding tie; the emission in the tests keeps class k as argmax on [4k, 4k+3] (as §5.8 words it) but makes frame 4k strictly best.
2026-09-10 | `packages/align`: the `say` fixtures hold 10 lines (about 18 s) instead of 6-8 | 8 lines gave 14 s, a single 15 s ASR window; 18 s exercises the two-window path and the final partial window that §1 fixes.
2026-09-10 | `packages/align`: `LyricsSync.syncFromBuffers` tokenizes before separation | An empty token list (`AlignError("no alignable words")`) then fails in milliseconds instead of after a minute of Demucs.
2026-09-10 | Root `scripts/fetch-models.ts` imports the engine through relative `../packages/*/src/index.ts` paths | The root package declares no dependency on the workspace packages, so `@musicbutler/align` does not resolve from `scripts/`; the root package.json is outside this task's ownership.
2026-09-10 | `packages/align`: `separate?: boolean` (SyncOptions, SyncCallOptions, CLI `--no-separate`) skips Demucs; both models load lazily through memoized `ensureAsr`/`ensureDemucs`, `load()` loads what the constructor implies | The server's `isolateVocals: false` (docs/PLAN.md §6.2, §12.6) must run without a Demucs session and without the Demucs weights on disk; `separate: false` fires no `separate` progress events, and a per-call `separate: true` still lazy-loads Demucs.
2026-09-10 | The Docker runtime runs `bun apps/server/src/index.ts` directly instead of a `bun build` bundle | Bundling `onnxruntime-node` and `sharp` (native addons) with `bun build` is fragile; Bun executes TypeScript natively, so the source plus pruned production `node_modules` is the "server bundle" (§9.2).
2026-09-10 | The Italian model stays unavailable in both image tags until an ONNX export exists; `latest-multilang` is still published so the tag contract from §13.16 is in place | No published ONNX export of an Italian wav2vec2 CTC model was found and the plan forbids publishing one without asking (§12.7).
2026-09-10 | `release.yml` re-runs the CI checks in a `verify` job that gates the image job, instead of chaining on `ci.yml` through `workflow_run` | Same guarantee (§9.4 "do not run the release job when ci.yml fails") with one workflow file and no cross-workflow status plumbing.
2026-09-10 | The confirm dialog carries two toggles, "Isolate vocals" (default on) and "Word timestamps" (default on); the no-dialog path reuses the same stored values | §12.4 and §12.6 defaults. The values live in the Zustand store so both paths of the §7.5 state machine send the same options.
2026-09-10 | "Delete lyrics" asks for confirmation in a dialog before it saves the empty document | §7.3 marks the button destructive; removing a file on a single click is too easy to do by accident. Cancel has focus, as in the sync dialog.
2026-09-10 | The sync write stage preserves the metadata tags found in the editor text (`[ti:]`, `[ar:]`, …) and adds none of its own | §8.2 drops metadata from the *lyric source* only; the user's tags are not ours to discard. §5.10's optional `[re:musicbutler]` header is not listed in §8.2, so it is not written.
2026-09-10 | The dev-time sync engine module is imported lazily (`await import("@musicbutler/align")`) inside `apps/server/src/sync/engine.ts` | `packages/align` reads `MUSICBUTLER_CACHE` at module load; a static import would run before `getEnv()` exports it (§13.14).
2026-09-10 | Image name is `ghcr.io/andreazllin/musicbutler` | The user confirmed the GitHub owner (PLAN §12.5).
2026-09-10 | ASR models are `facebook/wav2vec2-large-960h-lv60-self` (en-US) and `jonatasgrosman/wav2vec2-large-xlsr-53-italian` (it-IT), exported to ONNX once with `packages/align/scripts/export-asr-onnx.py` and published as `andreazllin/<name>-onnx` | The user chose these two models. Neither has a public ONNX export, and the Bun runtime loads ONNX only, so the export is a one-time step. English mean word score on the speech fixture rose from 0.83 (base-960h) to 0.93.
2026-09-10 | The export script lives in the repo (`packages/align/scripts/export-asr-onnx.py`) even though it is Python and runs outside Bun | Reproducibility: the published ONNX files must be re-creatable. The venv and outputs stay outside the repository (`~/.cache/musicbutler/export`).
2026-09-10 | Quantization constant-folds the graph first (`quant_pre_process`) and falls back to quantizing MatMul/Gemm only | wav2vec2's weight-normalised positional conv has a computed weight that `quantize_dynamic` rejects; the fallback keeps that conv in fp32. The English model took the folded path, the Italian one the fallback (355 MB).
2026-09-10 | ONNX model repos live under the Hugging Face namespace `linandrea` (not the GitHub owner `andreazllin`) | The user's HF username differs from the GitHub owner; the 403 on repo creation came from the wrong namespace.
2026-09-10 | `release.yml` builds amd64 and arm64 on native GitHub runners (`ubuntu-latest`, `ubuntu-24.04-arm`) and merges the digests into a manifest list, instead of one QEMU build | §9.4 allows this split; Bun under QEMU is slow and fragile, native builds took ~8 min per architecture. The first run only failed on artifact names containing ":" (fixed by stripping the `sha256:` prefix).
2026-09-11 | Root `bun run dev` uses `scripts/dev.ts` (two `Bun.spawn`s) instead of `bun run --filter` | `--filter` orders scripts by workspace dependency; web depends on server, so Vite waited forever for the server watch process.
2026-09-13 | The library tree is Mantine `Tree` + `useTree`, with directory listings loaded through `onLoadChildren` | It replaces the React Aria tree and the hand-written `LazyDirectory` component, and keeps one-level-at-a-time loading. `useTree` keeps its first-render callbacks, so the audio-versus-directory check reads a ref; closing over the node data made every folder click select the folder as a song.
2026-09-13 | The `song` query parameter is base64url, not the plain library path | The path showed the folder layout of the user's library in the address bar and in any screen share. base64url (RFC 4648 §5) rather than standard base64 because `+`, `/` and `=` are percent-encoded in a query string, and `/` would put the separators straight back. It is obfuscation, not a security boundary: the server still checks every path. A malformed value decodes to null, so an older plain-path link opens with no song selected instead of erroring.
2026-09-13 | The `song` parser rejects any path that is not a supported audio file, and the editor column shows an empty state when nothing is selected | One guard covers the tree click, a stale link and a hand-edited parameter: `lrc.get` answers "audioPath must point to an audio file" for a directory, which surfaced as an error panel. Rejecting in the parser means the screen never holds a path the server would refuse. With no song the column now renders `NoSongSelected` instead of a disabled editor and player, so the disabled-everything state is gone and the header carries a close button.
2026-09-13 | The editor's active-line, selection and search-match backgrounds are `color-mix` with transparency, not solid colors | CodeMirror draws the selection in `.cm-selectionLayer` at z-index -2, behind the line elements, so the solid `--mantine-color-default-hover` on `.cm-activeLine` hid the selection completely on whichever line held the cursor. Translucent backgrounds let the layer through; the selection moved to 32% of the brand color so it reads against them in both schemes.
2026-09-13 | The audio player draws no surface of its own | It is the header row of the sync-checker card, which already has the border and the divider below it. A `Paper withBorder` inside a `Paper withBorder` read as a box in a box.
2026-09-13 | Transactions the LRC editor dispatches itself carry a `programmatic` annotation, and the change listener ignores them | The listener reported every `docChanged`, including the component's own document replacement. Switching songs replaces the document with the next song's content while `lrc.get` is still pending, which is the empty string, so the empty document was written into the unsaved buffer: the new song opened blank and marked "Unsaved changes". The annotation lives in `editor/programmatic.ts` so the guard can be tested without a DOM.
2026-09-13 | `FileTree` reads `onSelectAudio` from a ref | Same `useTree` staleness as the directory check: the handler passed on the first render is the one that keeps being called, so the caller's unsaved-changes test was frozen at its first value and switching songs from the tree discarded unsaved edits without asking. The header's close button was unaffected, which is why it prompted and the tree did not.
2026-09-13 | The tree opens the path down to the selected song on a deep link or a reload, through `ancestorsOf` | The listings already load one level at a time, so any nesting depth works, but the tree started collapsed: the song was open in the editor with nothing to say which folders led to it. That is tolerable at `Artist/Album` and useless in a library of unknown shape. The chain loads top down, because `mergeAsyncChildren` can only graft a directory on once its parent is there, and it costs one request per level, once. Picking a song in the tree finds every ancestor open and skips the whole thing.
2026-09-13 | `library.tree` walks the whole library in one call, and the web tree holds it all, reversing §6.2's "never walk the whole library" | The filter could only ever narrow what the user had already opened, which is useless for finding a song in a library whose shape you do not know. Searching everything means holding everything. The walk is cheaper per entry than `listDir` because the tree needs neither size nor mtime, so a plain file costs no `stat`; directories are visited one at a time to bound open descriptors; a directory whose real path was already seen is skipped, which stops a symlink to an ancestor looping; and the count stops at `LIBRARY_TREE_MAX_NODES` (50,000), reported as `truncated` so the UI says the list is short rather than pretending it is whole. Rendering stays bounded because Mantine only draws expanded nodes.
2026-09-13 | Saving patches `hasLrc` in the cached tree instead of invalidating it | Invalidating would walk the whole library again to learn what one write already settled. `withHasLrc` walks only the branch holding the path and shares every untouched node.
2026-09-13 | The filter is fuzzy, matches name or full path, and is client side | Exact substring matching made the box brittle: a typo or a half-remembered name found nothing. Terms are split on whitespace and each must match in any order, so "deep level5" and "level5 deep" both work. Matching the path as well as the name is what lets a folder term and a song term combine. The tree is already in memory, so the server does no matching.
2026-09-13 | The filter draws at most `MAX_FILTER_RESULTS` (300) rows and says when it stopped | Matching the whole library is cheap: 36 ms over 9,160 nodes. Drawing is not. A broad query matched 2,824 rows and took 1.7 s per keystroke. Capping the rows brought that to about 300 ms, and the input is debounced by 150 ms so a keystroke does not redraw before the next one lands. Virtualising would lift the cap, but Mantine's `Tree` does not virtualise and flattening it would cost the keyboard handling; nobody reads the four thousandth hit anyway.
